# Подключение к КФБ

Откройте «Интеграции → КФБ» под пользователем SUPER_ADMIN.
Выберите тестовый локальный FIX_GateWay или боевой 172.23.10.84,
введите токен КФБ и нажмите «Подключиться».

Один API-токен используется для REST (Authorization: Bearer) и gRPC
(metadata authorization: Bearer). Токены сохраняются отдельно для серверов.
Пустое поле сохраняет ранее установленный токен выбранного профиля.
Сам токен никогда не возвращается в интерфейс. Настройки хранятся в
PostgreSQL зашифрованными AES-GCM с ключом, производным от JWT_SECRET.
Сохраняйте JWT_SECRET вместе с резервной копией базы.

Клиентский сертификат, приватный ключ и HMAC не требуются. В форме нет
загрузки сертификатов и настройки TLS-имени. gRPC использует TLS 1.3,
системное хранилище доверия и стандартную проверку имени сервера.
Ранее установленный оператором CA может использоваться как дополнительный
доверенный корень; пользователь не обязан загружать CA через интерфейс.
Проверка TLS не отключается. Если сертификат сервера не доверен системному
хранилищу или имя не совпадает, поток gRPC не откроется.

Выбор профиля заполняет форму. Подключение меняется после нажатия кнопки.
API применяет настройки сразу; worker перечитывает их каждые 2 секунды.
Подписка gRPC переподключается автоматически. Активный сервер указан внизу
страниц. Тестовый шлюз из Docker: REST http://host.docker.internal:8080/api/v1 и gRPC host.docker.internal:8443. Боевой шлюз: 172.23.10.84, REST 8081 и gRPC 8443. Адрес 192.168.0.89 относится к QUIK, брокерское приложение к нему напрямую не подключается.

Настройки сохраняются в system_settings, ключ kfb.connection.v1. При отсутствии
сохранённого токена используется KFB_GATEWAY_TOKEN из окружения для совместимости
с прежней конфигурацией. Доступ к GET/PUT /v1/integrations/kfb/settings ограничен
ролью SUPER_ADMIN. Токены и их значения не записываются в аудит.
