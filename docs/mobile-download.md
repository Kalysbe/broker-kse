# Прямая загрузка мобильного приложения

Сайт раздаёт Android APK по адресу `/downloads/kfb-invest-android.apk`. Ссылка
появляется только при наличии подготовленного файла. Google Play и App Store
для текущей сборки не используются.

## Подготовка

Исходный APK находится в `mobile/artifacts/kfb-invest-android.apk`. Из корня
репозитория выполните:

```powershell
npm --prefix frontend run prepare:mobile
```

Скрипт без дополнительных зависимостей копирует файл в
`frontend/public/downloads/kfb-invest-android.apk` и обновляет
`frontend/src/mobile-release.json`: доступность, URL, версию, размер, SHA-256,
канал `test` и требования `Android 7+ · ARM64`. Версия читается из
`mobile/app.json`; в изолированной сборке используется версия подготовленного
манифеста, а при отсутствии обоих файлов — `0.1.0`.

Бинарник в `public/downloads` исключён из Git. Манифест генерируется заново
перед `npm run dev` и `npm run build`; его наличие само по себе не подтверждает
доступность APK.

Если в полном checkout папка `mobile` существует, но исходный APK отсутствует
или пуст, скрипт удаляет прежнюю копию из `public/downloads` и записывает
`available: false`, пустые URL/SHA-256 и нулевой размер. Интерфейс должен
проверять `available` перед выводом ссылки. Ошибки чтения, записи и повреждённый
`app.json` останавливают подготовку, чтобы сборка не продолжилась со старым
манифестом.

## Docker

Контекст сборки frontend — папка `frontend`, поэтому `mobile/artifacts` внутри
контейнера недоступна. APK необходимо подготовить **до** сборки образа:

```powershell
npm --prefix frontend run prepare:mobile
docker compose build frontend
```

Существующий Dockerfile копирует `public/downloads` в образ сборки, а Vite — в
`dist/downloads`. При отсутствии соседней папки `mobile` скрипт принимает уже
подготовленный APK из `public/downloads`, заново вычисляя его размер и SHA-256.
В изолированном контексте версия берется из подготовленного манифеста полного checkout.

Если APK отсутствует и в исходниках, и в `public/downloads`, сборка сайта
выполняется с `available: false` и без ссылки на скачивание. Удаление всей папки
`mobile` при сохранённой копии в `public/downloads` трактуется как изолированный
контекст; для отключения загрузки в таком контексте удалите подготовленный APK
и повторите `prepare:mobile`. Перед Docker-сборкой обновите манифест скриптом полного checkout, чтобы передать актуальную версию приложения.

После сборки проверьте, что GET `/downloads/kfb-invest-android.apk` возвращает
APK, размер и SHA-256 совпадают с манифестом, а отсутствующий файл отвечает 404,
а не HTML главной страницы. Настройка HTTP-раздачи и заголовков скачивания
выполняется в конфигурации frontend/Vite и nginx.

## Статус текущей сборки

APK предназначен для внутреннего тестирования: ARM64, Android 7+, версия 0.1.1 (versionCode 2),
идентификатор `kg.sbis.mobile.localphone`, локальная тестовая подпись. Приложение
обращается к API `http://172.23.10.97` и работает в сети брокера при доступном
сервере. Публичная ссылка на загрузку не делает API доступным из интернета.
Для перехода со старого адреса 192.168.20.96:18080 необходимо установить обновленный APK. Внутренняя сеть сервера должна быть доступна с телефона. Полная инструкция
по установке и подключению находится в `mobile/README.md`.

Готовой iOS-сборки и ссылки App Store в репозитории нет.

## Публичные страницы и мобильный вход

Неавторизованный посетитель `/` видит рекламную страницу. `/welcome` открывает
её независимо от сессии; `/download` содержит APK, сведения о файле и инструкцию.
Для авторизованного пользователя `/` по-прежнему открывает рабочую панель.
Остальные рабочие разделы сохраняют проверку авторизации.

При открытии кабинета с телефона появляется предложение перейти к приложению.
Android получает ссылку на страницу загрузки, iPhone — объяснение совместимости
и возможность продолжить в браузере. Отказ запоминается в `sessionStorage`
на текущую сессию. Закрытие и Escape тоже считаются отказом.

Vite и nginx отдают APK как `application/vnd.android.package-archive` с
`Content-Disposition: attachment`; отсутствующий файл возвращает 404.

Проверки и снимки находятся в `frontend/design-evidence/`. Из корня проекта
`node frontend/design-evidence/check-download.mjs` проверяет работающий сайт
на `http://localhost:15173` (или `MARKETING_TEST_URL`), заголовки APK, размер,
контрольную сумму и ответ 404. `device-test.html` — только локальная QA-страница
с синтетическими Android/iPhone User-Agent; в production-сборку Vite она не входит.
