# События заявок KFB

При подключённой КФБ список `/v1/orders` читает `/api/v1/orders` выбранного
сервера, включая все страницы ответа. Состав списка, статусы и суммы определяет
биржа. Локальная история и нагрузочные записи не добавляются к этому списку;
при ошибке биржи возвращается ошибка, при пустом ответе — пустой список.
Сопоставление по ID шлюза или полному номеру QUIK сохраняет локальные ID для
выбора счёта и отмены. Заявки, введённые вне приложения, также видны; без
локальной записи кнопка отмены недоступна. Доступ клиента ограничен его кодом,
даже когда торговый счёт общий.

API держит одну исходящую подписку `fixgateway.realtime.v1.RealtimeService/Stream`
на `order.updated`, `marketdata.tick` и `positions.updated`. Соединение использует TLS 1.3, проверку CA и имени сервера,
клиентский сертификат mTLS и Bearer-токен `KFB_GATEWAY_TOKEN`, общий с REST.
После разрыва соединение восстанавливается с задержкой
от 1 до 32 секунд. Секреты и сертификаты не передаются браузеру.

Событие сопоставляется с локальной заявкой по `venue_order_id`. Исходный DTO,
снимок состояния, изменение локального статуса и уведомление outbox сохраняются
в одной транзакции. Биржевой номер QUIK хранится отдельно от ID шлюза.
Старое событие с `updated_at` раньше сохранённого снимка не меняет состояние.

Браузер использует одно WebSocket-соединение `/v1/realtime/ws` для запросов и
обновлений. Access token передаётся первым сообщением, без токенов в URL.
Проверяются сессия, права, брокер и клиент заявки. Подписки на рынок, выбранный
стакан, позиции и заявки доставляют полные ответы прямо в кэш интерфейса;
несколько событий объединяются за 250 мс. Сессия перепроверяется перед запросами
и отправкой снимков, а также каждые 20 секунд. После переподключения снимки
загружаются через WebSocket. Протокол описан в `websocket.md`.

Шлюз не гарантирует replay. После подключения или переподключения API сверяет
незавершённые заявки через REST партиями по 100, с общим лимитом чтения 100/с.
При рабочей подписке дополнительные проверки нужны для ещё не подтверждённых
заявок. Если подписка отключена, запускается резервная партия каждые 30 секунд.
Карточка загружает полную историю шлюза при первом открытии; кнопка «Обновить»
запрашивает её повторно. В обычном режиме события обновляют сохранённый снимок.

Настройки: `KFB_GRPC_TARGET`, `KFB_GRPC_SERVER_NAME`, `KFB_GRPC_CA`,
`KFB_GRPC_CERT`, `KFB_GRPC_KEY`, `KFB_GATEWAY_TOKEN`.
Локальные сертификаты находятся в игнорируемой папке `backend/certs` и монтируются
в API read-only. Docker build исключает их. При ротации заменить сертификаты и
перезапустить API. Protobuf-контракт хранится в `backend/proto/kfbrealtime/v1`.

Проверки: `go test ./internal/app ./internal/adapters/kfb`. Интеграционные проверки
требуют `KFB_TEST_DATABASE_URL`/`KFB_TEST_REDIS_URL`. Read-only проверка настоящей
mTLS-подписки дополнительно использует `KFB_REALTIME_TEST_URL` и настройки выше.

Позиции поступают полным снимком cash/instruments через positions.updated и заменяют
предыдущий снимок в Redis, включая пустые массивы. API /v1/positions и внутренние
проверки позиций используют этот снимок при подключённом потоке; пока снимок
не получен или поток отключён, используется REST. При переподключении старый
снимок удаляется. Фильтр по коду клиента в API сохраняется.
