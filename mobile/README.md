# КФБ Инвест · React Native

Мобильное приложение на Expo SDK 58 / React Native 0.88 / TypeScript. Интерфейс основан на [Figma](https://www.figma.com/design/spMjzIpFoU4aLcdq37MLZW/Untitled?node-id=0-1). Подключены существующий Go API, авторизация, счета, деньги, портфель, рынок, заявки, отмена, журнал и уведомления.

## Запуск с тестовой КФБ

Во время разработки используется существующий брокерский бэкенд и тестовая КФБ **http://localhost:8080**. Схема: приложение → Go API **http://192.168.20.96:18080** по локальной сети → тестовый шлюз. На самом ПК API также доступен по **http://127.0.0.1:18080**. Из Docker адрес шлюза — **http://host.docker.internal:8080**, gRPC — **host.docker.internal:8443**. Выбран сохранённый профиль **test** с его собственным токеном; биржевой токен не передаётся мобильному приложению.

Из каталога mobile:

```powershell
npm ci
# В .env.local: EXPO_PUBLIC_DATA_SOURCE=kfb
npm run backend:start
npm run android:start
```

API использует существующую базу broker_app; пользователи и пароли не пересоздаются. В приложении входите существующей учётной записью брокерского приложения. CORS включает web-предпросмотр **http://127.0.0.1:8082**. Для обновления статического предпросмотра: npm run export:web, затем npm run preview.

Для проверки соединения: **npm run test:kfb**. Проверка использует существующие серверные учётные данные из корневого .env, не печатает пароль/токены и требует профиль test с локальными REST/gRPC адресами и включённой тестовой торговлей. Пустой запрос заявки должен вернуть 422 до обращения к БД/бирже; действительные заявки проверка не создаёт.

**Текущий режим — тестовая торговля**: EXCHANGE_READ_ONLY=false в backend/compose.yml, выбран профиль test на localhost:8080. Режим просмотра сохранён в API: EXCHANGE_READ_ONLY=true блокирует изменяющие запросы и фоновую отправку/отмену заявок. Технические сведения о контуре и подключении не выводятся в клиентском интерфейсе.

Рынок показывает инструменты, возвращённые биржей. Остатки/портфель читаются через /v1/accounts/{id}/exchange-portfolio с проверкой доступа к счёту и фильтром биржевого кода клиента, счёта и валюты. Отсутствующий денежный остаток/цена показывается прочерком; локальные проводки не подставляются вместо биржевых данных. Оценка бумаг использует среднюю цену позиции.

На проверке 22.10.2026 тестовый шлюз вернул 3 инструмента, работающий gRPC, доступный остаток клиента 10 000 000 KGS и пустой портфель бумаг; цены не переданы. При отсутствии котировки лимитная цена вводится вручную. Продажа доступна при наличии бумаг, а причины недоступности торговли выводятся рядом с действиями.

Старый изолированный mock-стенд dev/compose.yml сохранён только для regression-проверок. Его npm run dev:backend и npm run test:integration нельзя запускать одновременно с основным API: оба используют порт 18080. Данные mobile-client / Mobile_Dev123 относятся только к этому отдельному стенду.

## Android

### APK для телефона

Сборка 0.1.2 (versionCode 3) для современных Android-телефонов ARM64: **artifacts/kfb-invest-android.apk**. Интерфейс и Hermes встроены в APK; Metro не нужен. Это внутренняя тестовая сборка с отдельным applicationId `kg.sbis.mobile.localphone` и локальной тестовой подписью, она не заменяет сборку эмулятора и не предназначена для публикации в магазине.

```powershell
# Из mobile: собрать APK
node scripts/android.mjs phone
# Необязательная установка через USB вместо копирования APK вручную:
powershell -ExecutionPolicy Bypass -File scripts/install-phone.ps1
```

Скачайте обновленный APK с **http://172.23.10.97/download** и установите поверх прежней версии. Телефон должен иметь доступ к сети сервера **172.23.10.97** через Wi-Fi или VPN. Для работы приложения USB, отладка и Metro не нужны. Необязательный USB-установщик только устанавливает APK и открывает приложение; кабель после установки можно отключить. При нескольких телефонах укажите `-Device SERIAL`.

Автономный APK использует **http://172.23.10.97**. Для проверки с телефона откройте **http://172.23.10.97/health/ready** — ожидается `"ready":true`. API доступен по `/v1` через серверный Nginx. Входите учетной записью развернутого сервера; пароль администратора выдан при развертывании. Токен КФБ сохраняется отдельно через админку и не включается в APK.

Для старого локального стенда Compose публикует API на loopback и указанном LAN-адресе. Правило Windows Firewall **SBIS-Mobile-API-WiFi** разрешает TCP 18080 только из **192.168.20.0/24** на интерфейсе Ethernet 2. Для воспроизведения правила выполните backend/enable-wifi.ps1 от имени администратора. На развернутом сервере 172.23.10.97 приложение использует порт 80; доступ к порту 18080 телефонам не нужен.

В варианте localPhone HTTP разрешен только для адреса API выбранной сборки; по умолчанию это 172.23.10.97. Общий release не меняется. Валидатор приложения принимает HTTP по приватному LAN-адресу только при точном совпадении с EXPO_PUBLIC_API_URL сборки. Для другого сервера задайте EXPO_PUBLIC_API_URL перед сборкой: скрипт одновременно обновит адрес API и точное сетевое разрешение Android. После смены сервера старый APK нужно заменить новой сборкой. В APK нет сохранённых пользовательских сессий, паролей или биржевого токена.

### Сборка для разработки

Android Studio 2026.2.1.8 установлен в `C:\Program Files\Android\Android Studio`. SDK: `%LOCALAPPDATA%\Android\Sdk`. Нативный проект генерируется Expo; `android/` исключён из Git.

```powershell
npm run android
```

Команда настраивает JDK/SDK и создаёт отдельную нативную сборку в C:\sbis-mobile. Путь можно задать через ANDROID_BUILD_ROOT; он должен содержать только ASCII. Исходники и Metro остаются в текущем проекте. Папка сборки помечена источником; чужая папка не перезаписывается. Зависимости обновляются при изменении package-lock.json, нативный проект генерируется Expo. `npm run android:build` собирает debug APK для x86_64-эмулятора; `npm run android:start` запускает Metro отдельно. Для телефона используйте `npm run android` с подключённым устройством.

Отдельная папка нужна из-за ограничений Android Gradle Plugin и генератора React Native на пути с кириллицей. Короткий путь Unix sockets необходим установленной JBR 25. Создан AVD **SBIS_API_36** (Pixel 8, Google APIs x86_64); ускорение WHPX доступно.

Для Android Studio открывайте `C:\sbis-mobile\android`. Экраны редактируются в исходном `Broker_App\mobile\app` и `src`; для их изменения достаточно работающего `npm run android:start`. Техническая копия обновляется скриптом сборки. Настройки CMake находятся в `dev/android-native.gradle`, Metro остаётся доступен только через IPv4 loopback.

Готовый debug APK для x86_64-эмулятора: `artifacts/sbis-mobile-debug.apk`. Установка, вход, восстановление SecureStore-сессии, mock-заявка и выход проверены на API 36; подробности и снимки — [development-evidence/verification.md](development-evidence/verification.md). APK использует текущий JavaScript из Metro и не является автономной release-сборкой для магазина.

Debug на Android по умолчанию обращается к **http://10.0.2.2:18080**. Для debug-разработки телефона по USB: `adb reverse tcp:18080 tcp:18080` и `EXPO_PUBLIC_API_URL=http://127.0.0.1:18080` до запуска Metro. В debug HTTP разрешён debug-манифестом; самостоятельный APK localPhone использует отдельное правило для адреса сборки, по умолчанию **172.23.10.97**. Для другого API задайте `EXPO_PUBLIC_API_URL` до сборки; HTTP на приватном LAN разрешается только для явно указанного адреса. Публичные переменные Expo попадают в приложение: секретов в них быть не должно.

Release требует HTTPS API, подпись и отдельную проверку на устройствах. Локальная сборка iOS требует macOS/Xcode.

## Реализованное поведение

- Вход, опциональный TOTP, refresh одним запросом и выход с очисткой кеша. На Android/iOS токены сохраняются через SecureStore; web хранит их в памяти до перезагрузки. Пароль и TOTP не сохраняются.
- Права, счета, котировки и остатки берутся с API. Ответы проверяются Zod; деньги остаются десятичными строками. Избранное и скрытие сумм сохраняются по пользователю.
- LIMIT/DAY: ввод → проверка → отдельное подтверждение. Лот/шаг цены проверяются Decimal. Комиссия определяется серверным тарифом.
- Повтор запроса с теми же параметрами сохраняет `client_order_id`. При сетевой неопределённости можно проверить заявки. Статус и исполненное количество приходят от сервера.
- Заявки обновляются каждые 5 секунд, котировки/остатки — каждые 15 секунд в активном приложении. WebSocket ещё не подключён.
- Графики и доходность не подставляются из демоданных. Оценка портфеля использует учётную цену API. Переводы, KYC, push и биометрический вход — следующие этапы.

## Код и проверки

`app/` — тонкие маршруты; `src/features/` — экраны; `src/api/` — HTTP-клиент и схемы; `src/session.tsx` — SecureStore; `src/broker.tsx` — TanStack Query и настройки; `src/domain/order.ts` — точная арифметика; `dev/` — локальный стенд и интеграционный тест.

```powershell
npm run typecheck
npm test
npm run test:integration
npm run export:web
```

Интеграционный тест запускается после `npm run dev:backend`, жёстко привязан к loopback:18080 и синтетическим идентификаторам. Он проверяет контракты, CLIENT, refresh, повторную заявку, конфликт параметров, отмену и сохранение денег при отклонении. В Go исправлены поиск повторной заявки по брокеру счёта и откат неуспешного резерва.

`design-evidence/` содержит скриншоты предыдущего демопрототипа. Новые результаты проверки сохраняются в `development-evidence/`.

`npm audit` на 21.10.2026 показывает 26 замечаний (19 high, 7 moderate), преимущественно в цепочке Expo/Metro. Автоматический `--force` предлагает несовместимый откат до Expo SDK 44 и не применялся. Замечания требуют устранения до выпуска.

## Обновления без APK

Начиная с 0.1.2 обновления интерфейса и логики предлагаются и загружаются внутри приложения. Подготовка и публикация: [обновления приложения](../docs/mobile-updates.md). Старые APK требуют однократной установки новой базовой сборки.
